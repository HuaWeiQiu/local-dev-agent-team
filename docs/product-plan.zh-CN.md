## 1. 一句话定位

**给会 Git、本机已有 Agent CLI 的人用的本地软件交付团队。**

它不是模型供应商，不是云 IDE，不是自动合并机器人，也不是通用多 Agent 操作系统。

承诺只有这一句：

> 你选一个可信的本地仓库，写清目标和约束。我用多个已登录的本地 Agent，在隔离 worktree 里改代码，用真实命令验收，最后按规范提起正式 PR。合不合并由你决定。

## 2. 给谁用，不给谁用

### 2.1 目标用户

- 自己写代码、会用 Git 和 GitHub 的个人开发者
- 本机已经安装并登录了 Codex / Claude Code / Grok / Kimi 至少一种
- 愿意让 Agent 改**自己的**仓库，但要求可审计、可回滚、不自动合并

### 2.2 明确不是谁

| 不是 | 原因 |
| --- | --- |
| 不会 Git 的人 | 主工作区干净、分支、PR 都是硬约束 |
| 第一次用电脑的大众消费者 | 没有向导能替他准备世界 |
| 要把陌生仓库丢给 Agent 的人 | 本机 worktree 不是沙箱 |
| 想要「点一下自动合进 main」的人 | `autoMerge` 永远为 false |
| 想要账号云同步的团队 SaaS | 产品是 local-first |

### 2.3 对标

公平对比是 **GitHub Desktop + 本地 Agent CLI 的编排层**，或 Cursor 里「按任务改仓库并提 PR」那一段。

不要对标抖音、ChatGPT 网页版、或「人人都能用 AI 写代码」。

按这个尺子，当前大约是：专业工具 7–8 分，开发者消费级 4 分。方案的目标是把开发者消费级做到 **6.5–7**，同时守住专业工具的边界。

## 3. 产品原则（不可破坏）

1. **角色 ≠ CLI ≠ 模型。** 换模型不改工作流代码。
2. **控制面说了算。** 浏览器和桌面壳不直接起 Agent、不改 run 快照。
3. **确定性命令否决 LLM。** 测试红了就不能被模型说成绿。
4. **Git 可恢复。** 不 force-push、不自动合并、不删未经校验的 worktree。
5. **主工作区必须干净才能开跑 / 同步 / 建基地分支。** 这是安全，不是刁难；但解释和清理是产品职责。
6. **崩溃可解释、可续跑。** 不假装同一个 Agent 进程还活着。未完成波次换新分支重做。
7. **三套产物必须可对账。** Tauri 壳、控制服务、前端构建号不一致时要说人话。
8. **本机 worktree 不是沙箱。** 只用于用户自己的可信仓库。
9. **token 不落盘。** 模型密钥和 `gh` token 都不进项目配置或 run 状态。
10. **少加能力，先把已有能力讲清楚。** 演进 / 经验是实验室，不是首页。

## 4. 用户能走完的主路径

```text
打开桌面 App / 接入项目
  → 需要发 PR 时连接 GitHub（本机 gh 浏览器授权）
  → 主工作区有改动就进 Changes：勾选、Commit，必要时 Push
  → 确认 Git 能力（干净、有提交、可选同步远端默认分支）
  → 写目标（可改策略、CLI、base/head 分支）
  → 看阶段条：分析 → 规划 → 执行 → 验证 → 等人 → 发布 → 完成
  → 需要时：审批、问进度、暂停、从已合并波次继续
  → 预览正式 PR（可改标题/描述）→ 创建 → 等人合并
```

日常用户只应感觉到五件事：**仓库身份、未提交改动、目标、阶段、PR**。

## 5. 信息架构

| 层级 | 入口 | 给谁 |
| --- | --- | --- |
| 日常 | 运行、项目 Git | 每次干活 |
| 配置 | 编排（策略）、设置（本机 CLI） | 改怎么跑 |
| 实验室 | 演进、经验 | 调系统的人，默认不抢主屏 |
| 外壳 | 桌面启动器 / 项目坞 | 选项目、看版本、处理占用 |

阶段条是运行页的时间轴，也是动作入口：当前段若在等人，直接「处理审批 / 发布 PR / 从已合并波次继续」。

## 6. 已经落地的能力（到 2026-08-15）

### 6.1 交付控制面

- 总控 / 架构 / 研究员 / 执行 / 审查 / 测试，角色与 CLI、模型、推理强度解耦
- 依赖感知 DAG 或强制串行；独立 worktree；真实质量命令；有上限返工
- 暂停、检查点恢复、重试为新运行；不重连已死 Agent 进程
- 多项目工作区：每项目独立 supervisor、租约、账本、worktree

### 6.2 Git 与发布

- 可选 base 分支；按目标生成 `feature/<slug>` 工作分支
- 新建分支默认先 ff-only 同步远端默认分支
- 空仓库可手动 `git init` + 空初始提交
- 正式 PR（新项目默认非草稿）；发布前预览标题/描述
- 旧配置若仍是草稿，预览可勾选「仅本次正式 PR」
- 已存在草稿 PR 会 `gh pr ready`
- 不自动合并
- 应用内「连接 GitHub」：拉起本机 `gh auth login --web`，不落盘 token、不自建 OAuth
- Changes：主工作区文件勾选、仓级 +/-、Commit、当前分支 Push（禁止 force-push）

### 6.3 阶段与旁路提问

- 生命周期阶段条：目标分析 →（可选探索）→ 规划 → 执行 → 验证 → 确认 → 发布 → 完成
- 每段一句精简总结，不展示推理和原始输出
- 「问进度」只读快照，不影响主运行，会话可删

### 6.4 体验打磨 1–3（已完成）

1. 壳 / 服务 / 前端版本可见；不一致提示旧包。改 UI 用 `pnpm desktop:dev` 或重装 App。
2. 脏工作区列出文件，区分本地改动和 Agent 残留；可看 diff、stash；禁用操作写原因。
3. 演进/经验降为实验室；阶段条可点审批/发布/续跑。

### 6.5 仍保留、但不进主路径的能力

- 策略编排与自定义蓝图
- 受控策略演进（有硬上限，不自动改提示词/工具/发布逻辑）
- 经验库（候选 / 已验证 / 共享）

## 7. 系统怎么拆（产品需要知道的架构）

```text
桌面壳（Tauri）
  → 内置 Node 启动控制服务（dist/cli.js）
    → 端出工作台（web/dist）
      → REST/SSE
        → supervisor / workflow
          → 本地 Agent CLI（用户已登录）
          → Git worktree / gh
```

三套产物、三条生命线：

| 层 | 日常开发 | 给自己用 |
| --- | --- | --- |
| 壳 | `pnpm desktop:dev` | 重装 `/Applications/Agent Team.app` |
| 控制服务 | 仓库 `dist/cli.js` | App 内 `runtime/app/dist` |
| 前端 | Vite 5173 或服务端静态资源 | App 内 `runtime/app/web/dist` |

只刷新窗口、只重启旧 App，看不到源码改动。这不是 bug，要写在产品说明里。

信任边界：

- 控制面：状态、预算、权限、Git、发布
- 执行面：已登录 CLI + 本机 worktree
- 不要把「可恢复 Git」理解成「隔离沙箱」

## 8. 关键产品规则（已拍板）

1. 自动分支名：`feature/<goal-slug>`；PR 标题：`feat: <goal-summary>`；前缀可改。
2. 旁路提问：每 run 最多 20 条，回答 ≤800 字。
3. 空仓库：人点「初始化 / 空初始提交」，工具不自动 init。
4. 旧项目 `draftPullRequest: true` 保持；仅新项目默认正式 PR。
5. 重试 run：沿用原 base，head 用新的内部工作分支，避免撞名。
6. 同步只允许 fast-forward。
7. 自定义分支不得占用 `agent-team/` 前缀。

## 9. 路线图

### 现在：0.1 可用（已到达）

本机专家能走完：选项目 → 处理脏工作区 → 开跑 → 看阶段 → 审批 → 正式 PR。  
桌面需重装才能看到对应构建号。

### 下一刀：开发者消费级 6.5（1–3 之后的新增项）

A–F 与「首次成功」最小集已在本迭代落地（本机发现新构建、临时分支过滤清理、开跑/提问耗额度说明、续跑人话、旧构建号拒绝新 API、首次信任确认、实验室默认折叠、脏仓「先帮我收好」）。连接 GitHub + Changes 按 `docs/github-connect-and-changes.zh-CN.md` 落地。按顺序，仍然**不做**评测实验室 / MCP / Docker / 触发器 / 真实多仓库连跑 / 自建 OAuth：

| 顺序 | 项 | 目的 | 完成标准 |
| --- | --- | --- | --- |
| A | 桌面自动更新（Sparkle 或等价） | 结束「我改了桌面没变」 | 打开 App 能发现新构建并替换自己 |
| B | Git 面板过滤 + 一键只清 `agent-team/` 临时分支 | 面板不再像垃圾场 | 默认隐藏内部分支；清临时分支不动 `feature/*` / `main` |
| C | 开跑前用量提示；提问标明耗额度 | 钱和时间不再是惊吓 | 启动器和提问旁有上一轮区间或「会耗一次调用」 |
| D | 续跑人话 | 可恢复 = 用户觉得稳 | 按钮写「从上次已合并波次继续，未完成任务会新开分支」 |
| E | 旧客户端打新 API | 分发滞后是常态 | 错误是「请更新 App」，不是「发布失败」 |
| F | 首次对某仓库的信任确认 | worktree 不是沙箱 | 第一次开跑弹一句：将用你的身份在本机改这个仓库并可能提 PR |

### 再下一刀：首次成功（消费级分数从 4 往 6.5 拉的关键）

1. 安装器引导或探测默认 CLI，没有就说「先装哪一个、怎么登录」
2. 打开脏仓库默认可以「先帮我收好」（stash），不要只停死
3. 首次成功向导：选文件夹 → 没有 Git 就引导 init → 写一句目标 → 阶段条动起来
4. 日常模式默认只留运行；编排/实验室折叠

### 明确暂缓

- **4.** 用 3–5 个真实仓库连续跑打磨现场
- **5.** 评测实验室、统一 MCP host、Docker/远程执行、Issue/Webhook/定时触发
- 自动合并、云账号、自建 GitHub OAuth、隐藏 Git、对陌生仓库一键开工 / clone
- 把演进/经验做成首页卖点
- 模型训练 / 在线强化学习

平台能力仍以 `docs/multi-agent-completeness-roadmap.zh-CN.md` 为准，需要时再单独立项，不混进 0.1 主路径。

## 10. 成功标准

### 10.1 0.1 必须一直为真

- 干净仓库 + 已登录 CLI，能从目标走到正式 PR
- 测试红了不能被模型说成绿
- 不自动合并、不 force-push
- 桌面构建号和工作台构建号能对上，对不上有提示
- 脏工作区能看见文件并 stash，而不是只看到 `dirty-worktree`

### 10.2 下一阶段（A–F + 首次成功）算做成

- 新用户（会 Git、本机有一种 CLI）30 分钟内完成第一次「目标 → 阶段在动」
- 用户不再靠终端判断「是不是旧包」「为什么不能同步」
- Git 面板默认只看见人在用的分支
- 中断后再打开，用户能从按钮文案理解会怎样续

### 10.3 不要用这些当成功

- Agent 数量变多
- 演进循环跑得更欢
- 对标「一个提示词生成完整公司」
- 下载量或注册用户（当前没有账号体系）

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 用户以为桌面热更新 | 版本条 + 文档 + 最终自动更新 |
| 脏仓库被当成软件坏了 | 文件列表 + 人话 + stash |
| Agent 临时分支污染 Git 面板 | 过滤显示，稍后一键清理 |
| 额度耗尽看起来像任务失败 | 已有故障分类；UI 要写成「模型暂时不可用」 |
| 有人拿陌生仓库开跑 | 首次信任确认；文档写死信任假设 |
| 为消费级分数取消 Git 干净约束 | 禁止。只允许 stash/解释，不允许带脏工作区开跑 |
| 为「更像框架」拆控制面 | 禁止嵌入第二套编排运行时 |

## 12. 文档与发布纪律

- 改用户可见行为：先改对应设计文档或本文路线图，再改代码，再补测试。
- 改桌面可见体验：Bump `CONTROL_PLANE_BUILD` / `__APP_BUILD_ID__` / 壳 `expected_build`，三者同一字符串。
- 给自己用：`pnpm desktop:build` 后覆盖 `/Applications/Agent Team.app`，并完全退出再开。
- 日常改 UI：`pnpm desktop:dev`。
- 本文与 `docs/git-branch-pr-inquiry-design.zh-CN.md` §15 冲突时，以更新的一份为准，并回写另一份。

## 13. 现在立刻能对用户说的话

**能做什么**  
在你自己的 Git 仓库里，用本机已登录的 Agent，按阶段把一个目标做成正式 PR。

**不能做什么**  
不能在工作区很脏时偷偷开工，不能自动合并，不能保证合上盖再打开还是同一个 Agent 进程，不能把这个 App 当成沙箱。

**你要准备什么**  
Git、至少一种 Agent CLI、发 PR 时还要 `gh`。可在项目 Git 里点「连接 GitHub」，不必先去终端登录。工作区先干净，或在 Changes 里提交 / 让我帮你把改动暂存起来。

**怎么更新**  
看左下角版本。和发行说明对不上，就完全退出，重装 App。
