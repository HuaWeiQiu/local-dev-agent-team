# 企业内部使用 × 消费级手感 — 迭代方案

> 状态：迭代 1 已落地并通过测试（2026-08-15）
> 总案：`docs/product-plan.zh-CN.md`
> 范围：公司内部软件开发工作站，不是云平台，也不是大众 App

---

## 1. 定位

**公司内部用的、消费级手感的本机软件交付工作站。**

- 企业补：能发、能更、能限仓库、能查是谁跑的。
- 消费级补：少解释、少惩罚、脏了能收好、失败有按钮。
- 主路径不变：目标 → 阶段 → 审批 → 正式 PR。

身份先认本机的人 + 公司 GitHub，不上假账号中台。

---

## 2. 原则

1. 不自动合并、不 force-push、token 不落盘。
2. 开跑仍要求基地干净；默认可以「先帮我收好」再开，而不是先骂一句 dirty。
3. 只允许白名单远端（公司 org / 已登记 host），防止对陌生仓开工。
4. 更新走签名或至少本机/内网清单，不靠人肉对拷。
5. 演进/经验继续藏在实验室。
6. 评测实验室、MCP 中台、Docker 远程、多仓库连跑：本迭代不做。

---

## 3. 迭代 1（本轮执行）

| ID | 项 | 完成标准 |
| --- | --- | --- |
| I1 | 自动更新可发现 | 启动器检查本机/内网 `desktop-latest.json`，可安装到「应用程序」；开发壳说明走源码 |
| I2 | 仓库白名单 | `github.allowedOwners`：origin 必须落在允许的 GitHub org/host；未配置则只警告不拦（兼容现有个人仓） |
| I3 | 脏仓默认先收好 | 新建运行默认勾选「工作区不干净就先 stash 再开跑」；服务端执行 stash 后开跑 |
| I4 | CLI 引导 | 设置/启动器/新建运行：一种 CLI 都没装或都没登录时，给一页人话（装哪个、怎么登录），不要只灰按钮 |

验收：`pnpm check` + 相关单测 + 全量 `pnpm test` 循环到绿。

## 4. 迭代 2 / 3（本轮只写进文档，不开工）

**迭代 2：** 选仓 → init Git → 写目标 → 阶段条；三种软件模板（修缺陷/做功能/补测试）；审计导出。

**迭代 3：** 开跑前用量数字；临时分支定期清；编排进设置；高风险仓加强隔离提示。

---

## 5. 配置草案（I2）

```yaml
github:
  enabled: true
  remote: origin
  draftPullRequest: false
  autoMerge: false
  # 空数组或不写：不强制拦截（个人开发兼容）
  # 写了则 origin 必须匹配其中一个 owner（github.com/acme 或 acme）
  allowedOwners:
    - acme
    - github.com/acme-labs
```

匹配规则：解析 `git remote get-url origin` 的 host + owner；SSH/HTTPS 都支持。

---

## 6. 明确不做

自动合并、云账号、对非白名单仓一键开工、企业 SSO 中台、Docker 集群、把实验室做成首页。
